# 面试讲法｜AI 游戏关卡生成器评测系统

> 说数字之前先确认：评审一致性的数字目前基于**待作者人工复核的临时标注**（Grok Bot 按 rubric 盲标）。如果面试前还没完成人工标注，就**明确说**「参照是按 rubric 盲标的临时标注，下一步是多人标注」，千万别说成人工标注。生成侧的合格率、配对差、ICC、闭环提升也依赖这套评审，同样按「方向性结论」讲。

## 1 分钟版本
「我做了一个 AI 生成游戏关卡的评测系统。出发点是：生成已经很便宜了，真正卡住落地的是**判断生成得好不好**。咱们 Craft 岗位 JD 里写的『分层验收标准、标准题库、可跨版本对比』，讲的就是这件事。

我选文字冒险，因为它把关卡的本质『决策点加反馈』剥离得最干净，验证成本最低：216 关全量评审不到 ¥3。做了四件事：
- 一套 24 个 spec 的正交题库加对抗样例，每个 spec 采样 3 次，三组生成器对照；
- 规则层、判断题清单评审（三个模型家族各答一遍）、投票分流的分层门禁；
- 拿 40 关标注集、分开发集和留出集去检验评审本身，对比常数基线，测重测信度；
- 一个『评审反馈→定向重写』的闭环，按每个合格关卡的成本核算。

结果：调 Prompt 让 7B 合格率从 19% 到 61%，换 72B 到 89%，两个配对差的置信区间都不含 0。闭环再把 72B 推到 96%。

但我也发现两件反直觉的事：一是 7B 同一个需求生成三次，分数几乎完全看运气，只采一次去比较 Prompt 会被骗；二是评审在排序上可信，单关门禁还不行，所以我用三家评审的分歧来决定转人工，自动处理的一半关卡和参照的一致率是 90%。」

## 3 分钟版本（STAR + 产品判断）
**S｜背景**：AI 正在把做游戏交给普通玩家。Roblox Build 的创作者里 71% 没用过 Studio；腾讯这边有混元世界模型、造化工坊、创作大赛 AI 赛道。问题是新手不会判断质量，平台审不过来，模型团队说不清新版本是不是变好了。

**T｜目标**：做一个最小但完整的评测体系，回答三个问题：这一关能不能上线？新版本有没有变好？不达标时钱该花在哪？

**A｜做法**：
1. **题库**：主题×难度 18 格全覆盖，画像按拉丁方轮转，再加 6 条对抗样例（约束冲突、Prompt 注入、时间循环悖论等）。难度不是形容词，而是**可检验的结构**，比如普通关必须是 1 个 success、1 个 partial、1 个 fail，规则层就能查。每个 spec 采样 3 次，CI 按 spec 聚类算。
2. **分层评测**：10 项规则检查（5 项阻断）不花钱先拦一批。LLM 评审第一轮用的是打分，发现它偏宽松、逻辑维几乎全给 5 分；第二轮改成 19 道必须引用原文的判断题，由事先固定的公式合成分数，三个模型家族各答一遍。
3. **评审也要被评测**：40 关标注集，dev 15 关只用来估校准偏移，holdout 25 关只看一次。我加了常数基线防止被『往均值猜』骗，还测了重测信度和成对比较。
4. **闭环**：把评审答出的问题和原文证据交回同一个生成模型重写一次，再用一个不看清单的成对比较独立复核，防止『对着评审刷分』。

**R｜结果**：
- 合格率 19% → 61% → 89%（A/B/C），配对差 +42pp、+28pp，CI 都不含 0；换任何一个评审，排序都不变。
- 7B 同 spec 三次采样的 ICC 只有 0.05，72B 是 0.63：**小模型的方差本身就是产品问题**。
- 逻辑问题只有带思考的评审抓得到：关思考的两家在 40 关里一共判出 4 次，开轻思考的 GLM 判出 15 次。
- 闭环让 72B 从 89% 到 96%，7B 从 61% 到 75%；但 7B 重写成功率 36%，还不如直接重新采样（46%）。
- 每个合格关卡约 ¥0.018，**几乎全是评审成本**；按合格关卡算，72B 不比免费的 7B 贵。全部实验花了约 ¥7.4。

**我的产品判断**：评测系统的价值不在给出一个分数，而在**知道这个分数什么时候可信**。现在它可以做版本对比和分诊，还不能单独做门禁。下一步最值钱的不是更强的生成模型，而是真人标注和更稳的评审：转人工率每降一个点，省下的人审成本远大于 token 成本。

## 高频追问

### Q1：如何建立 LLM 能力评估体系，持续优化 AI 生成质量？（面试真题）
按「**定义 → 度量 → 校准 → 归因 → 闭环**」五步回答：
1. **定义**：先把「好」拆成可以独立改进的维度（逻辑、趣味、难度匹配、可玩），每个维度写 1–5 的锚点描述。能写成结构约束的就写成结构约束（比如难度对应结果分布），交给规则层。
2. **度量**：建标准题库，做正交覆盖加对抗样例，并分层：冒烟集、回归集、线上采样集。题库冻结并记录哈希，保证跨版本可比。评审用不同源模型，控制位置偏差、篇幅偏差和自偏好，多次采样。
3. **校准**：评审本身要拿人工标注检验，分开发集和留出集，报告 Spearman、加权 κ、MAE，**并且和常数基线比**。我的项目里 v0 在开发集看着不错、留出集就塌了，这就是为什么必须有留出集。
4. **归因**：badcase 打标签，走决策树。先排除评审误判，再按「工程 → Prompt → 换模型 → fine-tune」的顺序，从便宜、可逆的手段开始。
5. **闭环**：线上用玩家行为（完成率、选项分布熵、评分、分享率）反过来校准评审。当评测分高但完成率低时，说明 rubric 漏了维度。北极星是「创作成功率」。

### Q2：自动评测和人工评测的比例怎么定？
不定死比例，按风险和置信度分流：
- 规则层阻断 100% 自动；
- 正反序不一致、灰区分数、规则与评审冲突、儿童画像、新类型样例走人工；
- 其余抽 5% 监控漂移。

第二轮我把分流规则改成了**三个模型家族投票**：都说合格就自动通过，都说不合格就自动拦截（或进重写），有分歧才转人工。216 关里自动处理 51%、转人工 49%；在 40 个标注关卡上，自动处理那部分和参照一致 90%，集成评审单独做门禁会判错的 9 关里有 7 关被分歧信号送进了人工桶。

经济账是：人审 1–2 分钟一关（假设），评审一关约 ¥0.011，两者差两到三个数量级。所以**评审每降低 1 个百分点的转人工率，比把评审 token 成本砍半更值钱**；提升评审一致性就是在降本。冷启动 49% 偏高，路径是真人标注重估偏移、逻辑维交给推理型评审、提高评审重测信度。

### Q3：质量不达标，调 Prompt、换模型还是 fine-tune？
看失败类型：
- **「没按要求做」**（格式、难度结构、约束遗漏）：先调 Prompt。我的 A→B（同为 7B）合格率 19%→61%，配对差 +42pp，CI 不含 0。
- **「Prompt 写清楚了还做不到」**：大模型能做到、小模型做不到，就换模型或蒸馏。B→C 合格率 61%→89%，困难档 50%→72%。
- **「想不清楚」**（因果断裂）：先加「评审反馈 → 定向重写」。我实测下来，对 72B 很划算（重写成功 62%，合格率 89%→96%）；对 7B 反而不如直接重新采样一次（36% vs 46%）。所以小模型用「多采样 + 评审挑」，大模型用重写。
- **「不好玩、模板化」，并且需要稳定的项目风格**：在积累足够高质量标注之后，用 fine-tune 或 DPO。

原则是先便宜、可逆的手段，再昂贵、不可逆的手段。

### Q4：为什么先做文字冒险，不做 3D？
- **验证成本**：一关几百字，人 1–2 分钟读完；3D 必须真跑 playtest，单次成本高一到两个数量级（估算）。
- **可行性**：现成 LLM 就能出结构化 JSON。
- **聚焦本质**：关卡的核心是决策点和反馈，3D 的工程问题会淹没设计问题。
- **方法可迁移**：迁移到 3D 只需要换规则层（寻路、碰撞、数值）和证据采集（截图、录屏），rubric 和校准流程不变。Roblox 的四信号框架也是这个思路。

### Q5：你的标注只有 40 关，而且不是人标的，结论靠得住吗？
- 不完全靠得住，所以我把结论分成两档。
  - **稳的**：版本排序。每 spec 采样 3 次，CI 按 spec 聚类算，配对差都不含 0；换任何一个评审，A<B<C 都成立。
  - **不稳的**：绝对合格率和单关门禁。换评审，C 组合格率能从 56% 摆到 93%。所以绝对数我只当方向性结论，等真人标注校准。
- 还有一个容易被忽略的坑：参照分数集中在 3–4 分，常数基线的 MAE 天然就低。我的评审排序明显好于基线，MAE 只打平。所以门禁效果要看误放 / 误杀，不看 MAE。
- 下一步：至少 100 关、2 名标注者，先算人与人的 κ 作为天花板。

### Q6：LLM 当评委有哪些坑？
- 位置偏差：第一轮实测 26% 的关卡正反序差 ≥2，但没有固定方向。成对比较更严重，20% 的对子正反序结论相反。
- 推理不足：关掉思考的评审几乎判不出逻辑问题（40 关里 DeepSeek 4 次、Hunyuan 0 次），开了轻思考的 GLM 判出 15 次。逻辑维要路由给推理型评审。
- 自身不稳定：同一评审换 seed 重评，合格结论只有 82% 一致。评审的重测信度就是它准确度的上限。
- 篇幅偏差：我实测没有比人更偏爱长文。
- 自偏好：用不同源模型规避。
- 宽松或讨好：v1 天花板效应明显。
- 矫枉过正：v2 的严重度膨胀。
- 把需求本身的矛盾算到作品头上：v2 的「画像冲突」误判。
- 还有一个容易忽略的：**评审升级后口径会漂移**，所以评审要冻结版本号，升级前在固定标注集上重跑一致性。

### Q7：这个系统上线后怎么衡量价值？
- 北极星：创作成功率（发布且被完整游玩的关卡 / 发起生成的会话）。
- 过程指标：迭代收敛轮次、首次发布时间。
- 评测健康度：和人工的一致性、重测信度、三家族分歧率（= 转人工率）、正反序不一致率。
- 经济指标：每个合格关卡的成本（我实测约 ¥0.018，几乎全是评审成本）。

因果上不能只看「评测分高的关卡完成率高」，这里有题材和曝光位置的混淆。可以在门禁阈值附近做断点回归，或者分桶 A/B，估计评测门禁带来的真实提升。这块用的是我计量经济学背景里的方法。

### Q8：如果让你在 IEG 落地，第一个月做什么？
- 第 1 周：和策划一起，把「好关卡」拆成可检验的维度，定义分层验收标准，拿 50 个历史关卡做双人标注，算出人与人的天花板。
- 第 2–3 周：搭题库和规则层，评审先只做分诊。
- 第 4 周：拿两个模型或 Prompt 版本跑第一次跨版本对比，产出第一份 badcase 归因，和算法团队对齐「下个迭代先修哪类问题」。
