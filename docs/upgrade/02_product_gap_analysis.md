# Phase 0 · 产品差距分析

IEG 版面向游戏策划和 AI 研发团队。在文字冒险关卡场景中，用同一冻结题集比较生成方案，用经校准的评测与人工证据处理异常，再把确认的问题沉淀为可回归案例。WXG 版继续用于原有实验展示。

| 优先级与模块 | 可以直接复用 | 当前架构的缺口 | 最小改造 |
| --- | --- | --- | --- |
| P0 · Experiment Center | A/B/C 模型、模板、重复采样、脚本执行、usage 日志 | 脚本通过文件名识别样本，写固定目录；缺实验 ID、失败台账、执行方式和完整请求快照 | 在现有运行函数外加服务与持久化适配层；按实验、任务和重复序号排队；逐次记录响应、缓存命中和失败 |
| P0 · Dataset Center | 24 条需求及每个输出附带的 spec | 题库由网格配置派生，重建可能覆盖文件；既有 dev/holdout 以输出划分，跨 split 的 spec 有重叠 | 从 Tag 注册只读历史版本。新增冻结版本与变更记录，新评测按 spec 分组隔离开发与留出集 |
| P0 · Evaluation Engine | H1–H10、19 题清单、四维合分和规则封顶 | 非对象 JSON、对象内非法类型需要边界校验；规则仅给布尔和详情。单关卡 schema 缺角色、道具、状态和关系，完整跨节点校验没有输入依据 | 先加解析和 schema 适配，保留旧规则 ID、阻断语义。等结构化字段进入输入契约后，再增资源引用与可达性检查。无法运行的规则给 `NOT_CHECKED` |
| P0 · Judge Calibration | 三家族、维度校准、一致性指标、重测、聚类区间 | v3 仅抽查四个键，缺完整类型、证据匹配、响应状态和真实置信度记录。比较同时含模型、思考与选项顺序差异；历史模型标签不能代表真人可靠性 | 提取答案约束和证据验证，给每次 Judge 固定版本及排序参数。新增人工配对样本后，才给人机一致性和混淆统计 |
| P0 · Human Review / Triage | 盲标页和 CSV、历史分流投票脚本 | 没有后端审核记录、审核人或改判理由。旧三家语义否决均拦截，而新默认策略应把分歧、证据无效或语义低置信交给策划 | 沿用内容呈现和规则优先，新增审核记录、配置版本和改判事件。旧策略及其汇总作为历史冻结，新策略产生独立的决策记录 |
| P1 · Bad Case / Trace | 历史 Bad Case 报告、结构化规则、Judge 答案、重写前后内容 | 查到终态错误时，历史文件常缺真实节点输入输出。推断无法稳定归因到首次偏离 | 以生成/解析/规则/Judge/分流/重写的真实步骤记录事件，根因假设与人工确认分别保存；历史缺失位置标记未知 |
| P1 · Golden Case / Rewrite | 现有重写函数、原/重写关系、重写复评与成对对照 | 无 Golden 批准机制、断言、候选发布入口；没有完整原/新 Prompt 快照与版本回归记录 | 一次重写上限，持久记录父子输出和同一评测配置；Golden 候选审批后发布冻结题库，重写质量需满足硬规则、关键维度和指定回归断言 |
| P1 · Regression / Decision Report | `stats.py`、`metrics.py`、历史三组比较、估算成本报告 | 归档口径混合费用估价、Judge 达标和人工验收；缺同一版本和同范围的比较视图，也缺失败尝试成本 | 确认配对键和固定评测口径，报告质量置信区间、难例子集、失败数、时延分位数、计价来源和人工样本量。先过明确质量门槛，再比较成本与效率 |
| P1 · 前端与本地部署 | 静态关卡详情、证据和重写浏览 | 交互配置、数据库查询、审查写入和后台状态需要本地 API；静态文件无法接收持久写操作 | 保留现有预览和标注呈现，逐阶段接入本地 API 和持久状态。新运行数据与已归档资料使用独立路径 |

优先验证的数据质量风险是四条解析失败被写为 Judge 分数占位、0 条真实人工标注、开发和留出集合跨 spec 重叠，以及重写成本复算差异。落地时把运行来源、原始证据与指标分母一起展示。新增功能若依赖上述缺失证据，应呈现对应的证据缺口。
