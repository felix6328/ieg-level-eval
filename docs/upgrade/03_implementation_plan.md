# Phase 0 · IEG 版增量实施计划

Phase 0 输出基线审计、数据血缘、差距分析与实施计划。Phase 1–6 为后续执行范围，各自有独立验收。下文描述的是计划契约。

## 版本与数据隔离

- `wxg-v1.0` 锁定稳定提交。IEG 分支 `ieg-v2.0` 在同级 Worktree `../level-eval-ieg-v2` 开发。历史归档以原文件 SHA-256 和 Tag 为来源，保留任务、样本、标签、证据和旧报表。
- IEG 第一份数据库由后续迁移初始化，使用独立文件及数据根目录。基线缺数据库，因此无需迁移 WXG 数据库；历史导入使用只读、幂等导入器。历史分析重算写入导入/复算批次的独立输出路径。
- 持久化每次生成和评测的数据来源。归档原始记录以历史实验存储；REPLAY 从已存生成文本重新检查或重放已有评审，附被引用的原记录标识；REAL 需要实际 Provider 请求和结果证据；MOCK 用于测试，排除出真实模型结论。复用原缓存时显式标记缓存与来源。原文缺失字段保持未知。

## 按阶段执行与验收

| 阶段 | 最小实现 | 验收证据 |
| --- | --- | --- |
| 1 · Experiment / Dataset | 在 Python 核心外加轻量本地 API、SQLite 数据服务和单机持久队列。实现 Project、Dataset、DatasetVersion、TaskCase、Experiment、ModelConfig、PromptTemplate、GenerationRun、GenerationOutput；冻结版本，登记模型/Prompt/温度/token 上限/重复/种子/评测配置。适配历史只读导入和 REPLAY，固定每次尝试、错误、原始响应和成本日志 | 24 条任务与 216 份归档精确对齐，导入重复执行不增行；不同 Prompt、模型和重复序号可查询；失败结果不丢；冻结数据可复跑。进程重启后状态恢复，历史 Replay 保证零生成调用 |
| 2 · Evaluation / Calibration | 保留 H1–H10 和 v3 作为独立规则/评审版本，增加 EvaluationRun、RuleResult、JudgeResult、schema 与证据验证。配对比较同一输出的多个 Judge；记录模型参数、重测与漂移范围 | 非法 schema、无效原文和未完成结果分类；复算保留历史；开发与保留集按 spec 隔离。人工不足时 Human-Judge 指标显示样本不足 |
| 3 · Human Review / Triage | 独立 HumanReview 与 TriageDecision，带来源、审核人、原因和审计事件；复用盲标交互和门禁逻辑，配置阈值与人工覆盖 | 三路分流及覆盖可追溯；历史路由单独展示。临时标注与模型辅助输出保持来源，真人确认有单独记录 |
| 4 · Bad Case / Golden / Rewrite | 用运行事件关联首次可观察偏离；BadCase 明确归因状态。GoldenCase 从草稿、验证、审批到发布、退役；重写最多一次，保留请求前后快照和同一评测配置 | 从 Bad Case 生成候选，经人工审核发布新数据集；旧版本仍可重放。重写能核对硬规则、关键维度、回归断言、成本与时延 |
| 5 · Decision / Regression | RegressionRun、DecisionReport 使用冻结数据和配对实验，按质量门槛筛选方案，再展示成本、效率、稳定性、人工负担 | 记录指标的分子、分母、来源、时间与样本量。金标不足显示观察结论。执行指定新/旧版本对照，能下钻到失败样本 |
| 6 · 前端整合和验收 | 接入实验、评测、分流、案例和报告页面，保留旧关卡呈现能力，从版本化数据与数据库取数 | 用三组历史 Replay 演示完整流程，随后以人工批准 Golden Case 数据版本执行回归。新增 REAL 用例以凭证和预算确认后实际运行 |

队列的请求标识按实验、数据版本、任务、配置和重复序号持久化。逻辑请求与 Provider 尝试分层记录，支持恢复和幂等。未确认模型服务是否支持请求幂等或远端可查状态前，超时后可能已计费的尝试应可审计；数据库不能证明远端只执行一次。新凭证仅从环境变量读取，历史 `.env` 拾取路径留在 WXG 入口。

## 指标与分母契约

所有百分比附计数、数据版本、运行模式、评测配置和时间范围。匹配条件不足或分母为零显示不可计算。评测门禁和人工验收使用各自指标。

| 指标 | 初始口径 |
| --- | --- |
| Generation Success Rate | 成功产出并完成结构解析的逻辑请求 ÷ 该实验范围内发起的逻辑请求总数。正式报告使用已封存的实验范围，实时看板另显示仍在运行、失败、取消和模型尝试数。重试保留在尝试表，避免重复计算逻辑请求 |
| Hard Rule Pass Rate | 所有适用阻断规则已检查且通过的输出 ÷ 已完成规则评测的输出。格式失败进入阻断。规则未完成、未适用或异常分开统计 |
| Human Acceptance Rate | 由人工确认合格的决策数 ÷ 同范围内已完成的人审数。待审和临时参照单列 |
| Auto Pass Precision | 同时自动通过且人审合格的配对数 ÷ 自动通过且已人审数。误放率按人审不合格样本为分母，误拦率按人审合格样本为分母。报告配对覆盖和抽样方式 |
| Judge Agreement / Dimension Difference | 一致判定数 ÷ 两位 Judge 对同输出都有可比较结果的配对数。分差用配对维度的平均绝对差。Cohen's Kappa 需相同类别口径和足够配对样本，分歧与缺失单列 |
| Evidence Validity Rate | 满足全部必需引文与结构要求的结果 ÷ 有证据验证义务的 Judge 结果数。无效、缺失以及无需引文按明确状态保留 |
| Review Rate | 转人工复核的输出数 ÷ 已完成分流的输出数。另报实际审核完成率与改判数 |
| Rewrite Success Rate | 重写后满足硬规则、关键维度及回归门槛的失败样本数 ÷ 已执行重写的失败样本数。缺少复评的执行进入未完成计数 |
| Cost per Accepted Output | 同一实验窗口中可追溯实际生成与评测费用（含失败或重试，拆列重写和复评） ÷ 最终经真人确认合格的输出数。假设价另做估算；账单或人工标签缺失时给出不可计算状态 |
| 耗时 | 生成、评测、审查与重写分别报可测任务的耗时和样本数，记录排队时间，标记顺序/并发执行。历史费用与时延沿用原报告口径并标记归档或复算 |

各阶段完成后重跑基线和本阶段验证，并比对历史归档的内容哈希。现有核心函数优先通过适配层接入，新接口只验证当前阶段能力。
